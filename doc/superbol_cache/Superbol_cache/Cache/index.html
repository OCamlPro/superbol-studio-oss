How an entry is looked up

An entry is addressed by a shallow key, built with shallow_key from what the caller knows before doing any work. The shallow key locates a manifest, which lists the witnesses that were observed while the work was done. A hit requires the manifest to be there and every one of its witnesses to still hold; anything else is a miss.

This is what gives the library its defining property without storing a graph: since a witness may be the key of another entry, a miss on a dependency --- however deep --- is a miss on everything that reused it.

Who performs I/O

The cache reads and writes only under its own root, through the Store record it was created with. Deciding whether a witness still holds is the caller's job, via the resolve argument of lookup: the LSP answers from the documents it has open, which may differ from what is on disk, while the CLI answers from the file-system. This is what makes a hit recorded against an editor buffer and a hit recorded against a file name interchangeable, as long as the contents agree.

Use Witness to build witnesses, rather than the constructors in Types: it applies the path canonicalisation that two spellings of one path must agree on.

Failure

A cache is optional. Every operation here reports a miss rather than a failure when the underlying storage misbehaves, and the Error cases that remain still only mean "carry on as though the cache were empty".

type t
val create : ?touch_granularity:float -> store:Store.TYPES.store -> unit -> t

create ?touch_granularity ~store () is a handle on the cache held in store.

A hit refreshes the date the entry was last used, which pruning relies on. Doing so on every hit would turn each read into a write --- ruinous on a shared network mount --- so the date is only refreshed once it is touch_granularity seconds stale. That bounds how far the recorded date lags behind reality, so keep it well under any pruning delay.

val disabled : t

A cache that misses on everything and stores nothing, for when caching is turned off.

val shallow_key : label:string -> inputs:Types.digest list -> Types.key

shallow_key ~label ~inputs is the key to look an entry up by; see Manifest.shallow_key. label is carried through to the monitoring API and is otherwise opaque.

Looking up and storing

val lookup : t -> key:Types.key -> resolve:(Types.witness -> bool) -> read_item:(string -> ('a, Types.read_error) Stdlib.result) -> ('a option, Types.error) Stdlib.result

lookup t ~key ~resolve ~read_item is Ok (Some value) when key has a manifest whose every witness resolve accepts, and whose value read_item decodes; Ok None on a miss.

resolve is never asked about a Types.witness.Sub witness: those are followed within the cache. It may be asked about the same witness more than once across a single call only if it is reached through unrelated entries; the answers are memoised for the duration of the call, so an expensive resolver need not memoise on its own.

val store : t -> key:Types.key -> label:string -> witnesses:Types.witness list -> write_item:('a -> (string, Types.read_error) Stdlib.result) -> 'a -> (unit, Types.error) Stdlib.result

store t ~key ~label ~witnesses ~write_item value records value under key, to be returned by a later lookup for as long as every one of witnesses keeps holding.

Storing over an entry that is already there is a success and leaves it alone: two instances that computed the same thing need not agree on which of them wins.

Monitoring and pruning

val entries : t -> (Types.entry_info list, Types.error) Stdlib.result

entries t describes every entry held, including those written by other producers sharing the same on-disk format.

val stats : t -> (Types.stats, Types.error) Stdlib.result

stats t aggregates entries and adds the identities t runs under.

val prune : t -> policy:Types.prune_policy -> (int, Types.error) Stdlib.result

prune t ~policy reclaims what policy allows, and is the number of entries removed; see Prune.run.

Pruning is the one operation that takes a lock, and is a no-op --- reported as Ok 0 --- when another instance is already at it.
